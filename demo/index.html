owg-css v0.1.0

Dense, monospace CSS for things that run in a terminal

One stylesheet. Write plain HTML (or let Markdown write it) and it looks finished: tight rhythm, Roboto Mono, thin rules, one cool accent. Classes are opt-in extras for the bits Markdown can't express. No build step, no utility soup, no JavaScript in the core.

accessibility

Accessibility

What owg-css guarantees today. Press Tab to walk this page.

text contrast
Every text colour is at least 4.5:1 in all 14 theme × variant looks. mise run check renders each look in Chromium, measures 138 colour pairs from real elements in real states, and fails the build below the line.
control borders
Inputs, selects, textareas, checkboxes and radios have a boundary of at least 3:1 against what surrounds them, in every look (WCAG 1.4.11). The same check measures it.
focus
Every focusable element gets a solid 2px :focus-visible outline: links, buttons, every input type, selects, summaries, sidebar and table-of-contents links, top-bar controls. The outline is at least 3:1 against its surroundings, with one known exception below.
forced colours
With forced-colors: active (Windows High Contrast), controls, checked states, focus outlines and the current sidebar or table-of-contents item stay visible in system colours. Checked with Chromium's emulation only, not on a real Windows machine.
right-to-left
The chrome uses logical properties, so with <html dir="rtl"> the sidebar, drawer, rails and table of contents mirror to the other side.
narrow screens
A wide table scrolls sideways inside its own box instead of stretching the page. At 320px and 390px none of the demo pages scrolls sideways.
your overrides
Element defaults sit in :where(), and the chrome's selectors are element types only, so one class of yours beats them. The exception is top-bar buttons, which keep their hover and pressed states. Your bare a {} or h2 {} rules don't leak into the top bar, sidebar or table of contents.
reduced motion
With prefers-reduced-motion: reduce, transitions, smooth scrolling and animations (cursor, status pulse, spinner) stop.
no JavaScript
The core is CSS only. The sidebar drawer opens with a #sidebar link, <details> folds natively, and light/dark follows the OS. owg-theme.js only adds a remembered choice and Esc to close.
your font size
The root is 87.5% of the browser setting and every size is in rem, so a larger default text size scales the whole page.
state in markup
Styles hang off ARIA you'd write anyway: aria-current, aria-invalid, aria-busy, aria-pressed.
print
Dark text on white, no sidebar or table of contents, link URLs printed, code wrapped.
not covered
Disabled controls are deliberately dim and below 4.5:1, as WCAG allows for inactive controls.
right-to-left
Code (pre, code, kbd, samp) stays left-to-right and isolated; badges take their direction from their own text. Hidden tooltips take no space, and shown ones stay inside the viewport.

components / callouts

Callouts

Note

The CLI reads ~/.config/notes/config.toml before environment variables.

Tip

Set NOTES_LOG=debug to see every SQL statement with its timing.

Important

Version 2 changes the on-disk format. Run notes migrate once after upgrading.

Warning

Port 5432 is open to the world in the default compose file. Bind it to 127.0.0.1.

Danger

notes purge --all deletes every note and attachment. There is no undo.

A bare .callout with no title and no type: just a quiet box for an aside.

Collapsible: known issues in 1.4

Attachments over 2 GB fail on 32-bit ARM builds. Use the 64-bit image on a Pi 4 or newer.

components / semantic html

Semantic HTML, no classes

Callouts and badges need no classes. Inside <main> or <article>, an <aside> is a callout and its first heading is the title. A <mark> in a heading, link, list item, table cell, <dt>, <summary> or button is a badge. A mark in running prose stays a highlighter. The class forms keep working.

Types come from data-type (note tip important warning danger, plus info success caution) or from ARIA role; a plain <aside> is the quiet one. Status badges: data-status="ok|warn|error|info".

Steps

  2. Log in

    notes login opens a browser and stores a token in your keyring.

  3. Create a vault

Syntax highlighting

    restart: unless-stopped
    environment:
      DATABASE_URL: postgres://notes@db/notes
      NOTES_LOG: info
    ports:
      - "127.0.0.1:8080:8080"
    depends_on: [db]
  db:
    image: postgres:17
    volumes: ["pg:/var/lib/postgresql/data"]
volumes:
  pg: {}
// healthz reports ready only once migrations have finished.
func healthz(db *sql.DB) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		ctx, cancel := context.WithTimeout(r.Context(), 2*time.Second)
		defer cancel()
		if err := db.PingContext(ctx); err != nil {
			http.Error(w, "db: "+err.Error(), http.StatusServiceUnavailable)
			return
		}
		w.WriteHeader(http.StatusNoContent) // 204
	}
}

# Nightly backup: dump, encrypt, ship.

echo "backup ok: $stamp"
